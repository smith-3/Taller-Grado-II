\section{Conclusiones}

\noindent En este capítulo se presentan las conclusiones obtenidas a partir del desarrollo del proyecto, en función del objetivo general y los objetivos específicos planteados.

\begin{itemize}
\setlength\itemsep{0.45em}\setlength\parskip{0pt}\setlength\parsep{0pt}

\item Al desarrollar el sistema de personalización, se identificó que los estudiantes poseen preferencias de organización contradictorias. Este obstáculo se superó implementando la clase ScheduleGeneratorUseCaseImpl, la cual utiliza un objeto GenerateParams para filtrar opciones basándose en días permitidos, evasión de conflictos y priorización de docentes favoritos, cumpliendo así el objetivo de flexibilidad mediante una configuración granular.

\item Durante la implementación del módulo de acceso rápido, se requería persistencia de datos sin navegación compleja. Se solucionó este problema mediante el ScheduleAppWidgetProvider, que utiliza RemoteViews y SharedPreferences para almacenar y visualizar el horario seleccionado directamente en el escritorio del dispositivo, facilitando la consulta inmediata sin abrir la aplicación principal.

\item La funcionalidad de exportación enfrentó limitaciones de memoria al generar imágenes de alta resolución. Esta limitación se resolvió con la implementación de HtmlToBitmapImageGeneratorImpl, que emplea un WebView fuera de pantalla y un Canvas para renderizar el HTML del horario directamente a un Bitmap optimizado, logrando una exportación eficiente en formato PNG.

\item Para la sugerencia de horarios optimizados, se reemplazó el enfoque inicial por un algoritmo recursivo implementado en la función backtrack dentro de ScheduleGeneratorUseCaseImpl. Este algoritmo integra una heurística computeGapPenalty que penaliza los tiempos muertos entre clases, minimizando eficazmente las ventanas vacías en las combinaciones generadas.

\item En la optimización de la interfaz de usuario, se abordó la confusión en la navegación mediante la clase AiManagementOnboardingScreen. Esta implementación utiliza componentes AnimatedEntrance para guiar al usuario paso a paso, asegurando una experiencia de introducción clara y reduciendo la curva de aprendizaje inicial.

\item La ingesta de datos académicos presentó desafíos debido a la estructura irregular de los archivos fuente. Fue necesario implementar la clase PdfParser con expresiones regulares que utilizan grupos con nombre (courseLine y scheduleLine) y una estrategia de mergeTeacherLines para normalizar las líneas de texto fragmentadas, permitiendo una extracción de datos robusta.

\item Aunque el proyecto enfrentó desafíos significativos relacionados con la calidad de los datos y la diversidad de dispositivos, la arquitectura implementada logró gestionar los horarios de manera eficiente. La validación técnica confirmó que componentes como el ScheduleGeneratorUseCaseImpl y el PdfParser permitieron superar estas barreras, cumpliendo satisfactoriamente el objetivo general del proyecto.

\end{itemize}

\section{Recomendaciones}

\noindent A partir de las limitaciones identificadas durante el desarrollo y el feedback de los usuarios, se presentan las siguientes recomendaciones orientadas a extender la funcionalidad de TecnoTime y mejorar su utilidad en el contexto académico real.

\begin{itemize}
\setlength\itemsep{0.45em}\setlength\parskip{0pt}\setlength\parsep{0pt}

\item Se recomienda implementar una funcionalidad de edición manual profunda en el repositorio de horarios. Actualmente, la inmutabilidad de los datos generados por ScheduleGeneratorUseCaseImpl impide reflejar cambios informales; permitir la modificación directa de los objetos GroupSchedule aumentaría la utilidad de la aplicación ante cambios de último momento.

\item Se sugiere integrar la gestión de actividades personales extendiendo el modelo de datos actual. Permitir que el algoritmo de backtrack considere eventos externos como restricciones adicionales transformaría la aplicación en un gestor integral del tiempo, cubriendo necesidades más allá del ámbito académico.

\item Se recomienda desarrollar un módulo de recordatorios vinculado a las entidades SubjectInfo. La capacidad de asociar metadatos de fechas de exámenes a las materias parseadas complementaría la organización temporal, ofreciendo una herramienta más completa para el seguimiento del rendimiento.

\item Para extender el sistema a otras facultades, se recomienda abstraer la lógica de ingestión de datos. La dependencia actual de las expresiones regulares específicas en PdfParser es una limitante rígida; se sugiere promover la implementación de una API REST institucional que provea objetos JSON estructurados, eliminando la necesidad de parsing de texto no estructurado.

\item Se recomienda a la institución formalizar un canal de distribución oficial para los archivos de horarios. La variabilidad en el formato de entrada que requiere ajustes constantes en las Regex del PdfParser podría mitigarse estableciendo un protocolo de validación de documentos fuente antes de su publicación.

\item Se sugiere explorar en trabajos futuros la incorporación de modelos de aprendizaje automático en el dispositivo. Estos podrían analizar los patrones de uso almacenados en UserSettingsRepository para ofrecer sugerencias proactivas de redistribución de carga académica, elevando el nivel de asistencia personalizada.

\end{itemize}
