\section{Fase 5: Interoperabilidad local y portabilidad JSON}

Esta fase se centra en habilitar un mecanismo robusto y estructurado para el intercambio de información académica administrada en el dispositivo por el estudiante. Se implementa un contrato de datos basado en JSON que encapsula la información del horario, permitiendo su portabilidad, respaldo y validación entre dispositivos. Además, se integran flujos de exportación e importación que aprovechan las capacidades de las plataformas de mensajería instantánea modernas, facilitando la difusión de horarios sin depender de una infraestructura de servidor centralizada.

\subsection{Objetivo}
El objetivo principal es permitir que los estudiantes compartan, importen y respalden sus horarios de manera interoperable, segura y eficiente. Esto implica eliminar la necesidad de transcripción manual dentro del flujo de organización personal, reducir errores en la comunicación de grupos y horarios, y garantizar que la información compartida sea compatible entre diferentes versiones de la aplicación, preservando la integridad de los datos académicos del usuario receptor.

\subsection{Alcance de la interoperabilidad}
La interoperabilidad implementada no corresponde a una integración transaccional con sistemas institucionales. La aplicación no modifica SAGAA, WebSIS, Cappuchino ni otros sistemas externos; tampoco automatiza la inscripción oficial del estudiante. Su alcance consiste en consumir información académica publicada de forma abierta, transformarla a un modelo local y permitir su intercambio mediante archivos estructurados.

Bajo este criterio, SAGAA se considera una fuente pública de horarios en formato HTML/PDF, WebSIS se mantiene como el sistema oficial donde el estudiante formaliza su inscripción y Cappuchino se reconoce como una herramienta de apoyo usada en el contexto académico. La aplicación se ubica en la capa personal del estudiante, por lo que organiza y transporta datos locales, pero no reemplaza los procesos institucionales.

La información de cupos y prerrequisitos no forma parte del alcance implementado, debido a que no se encuentra disponible en los documentos de horarios consumidos por el sistema ni está modelada en las entidades actuales. Estos datos requerirían acceso institucional adicional y reglas de negocio distintas a las desarrolladas en el proyecto.

\subsection{Implementación de la interoperabilidad}
La implementación técnica habilita la creación de múltiples formatos de exportación, abarcando representaciones visuales (PNG, PDF) para consumo directo y estructuradas (Excel, JSON) para manipulación de datos. Esta arquitectura flexible permite desacoplar la lógica de generación, delegando la construcción de cada formato a casos de uso especializados que garantizan la fidelidad de la información presentada.

El núcleo de la interoperabilidad se fundamenta en un contrato JSON auto-contenido, generado y validado en exclusiva por la capa de dominio. Para asegurar un intercambio seguro, se integran flujos que utilizan FileProvider de Android, exponiendo los archivos mediante URIs de contenido temporales. Este mecanismo incorpora validaciones estrictas y una lógica de importación idempotente que previene la corrupción o duplicación de datos en el dispositivo destino.

El intercambio de datos se organiza en diversos escenarios que responden a las necesidades de actualización, normalización y portabilidad del estudiante. \subsection{Exportar}
La exportación es orquestada por el SettingsSendScheduleViewModel, que gestiona los estados de la interfaz y delega la generación de archivos a casos de uso especializados. El sistema permite la externalización de la información en los siguientes formatos estándar:
\begin{itemize}
  \item Imagen (PNG): Generada por GenerateWeeklyScheduleImageUseCase.
  \item PDF: Generado por GenerateWeeklySchedulePdfUseCase.
  \item Excel: Generado por GenerateScheduleExcelUseCase.
  \item Copia JSON: Generada por GenerateShareableScheduleJsonUseCase.
\end{itemize}

El proceso de exportación JSON permite una selección parcial de materias. El GenerateShareableScheduleJsonUseCase recopila la información académica (carreras, materias, grupos, docentes, aulas) y utiliza el ShareableScheduleJsonGenerator para construir el archivo final. La compartición se realiza mediante un Intent.ACTION\_SEND con un FileProvider, asegurando la compatibilidad con aplicaciones de mensajería como WhatsApp.

\subsection{Enviar copia (JSON)}
El archivo JSON generado sigue un contrato estricto definido en ShareableScheduleJsonGenerator. Este recurso es auto-contenido, permitiendo reconstruir el horario sin depender de una conexión inmediata. La estructura jerárquica del contrato se compone de los siguientes elementos técnicos:

\begin{itemize}
  \item meta: Contiene la versión del contrato (version) y la versión mínima soportada (min\_supported) para garantizar la compatibilidad semántica entre diferentes versiones de la aplicación.
  \item careers: Lista de carreras implicadas (código y nombre) para permitir la sincronización automática si el receptor no tiene la carrera habilitada.
  \item subjects: Catálogo de materias para referencia.
  \item groups: Información de los grupos asociados.
  \item teachers: Datos de los docentes para enriquecer la visualización.
  \item classrooms: Información de las aulas.
  \item entries: Lista de las inscripciones (EnrolledSchedulePreview), que vinculan una materia y un grupo con un horario específico.
\end{itemize}

\subsection{Importar (desde WhatsApp)}
Al recibir un archivo JSON, la aplicación utiliza el LoadShareableScheduleUseCase para validar la integridad de la estructura y asegurar el cumplimiento del contrato de versión definido en los metadatos. Posteriormente, el ImportSharedScheduleUseCase orquesta la lógica de importación, la cual comienza verificando y sincronizando de forma automática las carreras faltantes si es necesario.

A continuación, cruza los datos entrantes con el repositorio local (SelectedSubjectRepository) para identificar materias ya aprobadas o inscritas. Se aplica una estrategia de fusión inteligente que garantiza la consistencia de la base de datos académica mediante los siguientes procesos de validación:

\begin{itemize}
  \item Sincronización de Carreras: Si el parámetro autoSyncCareers está activo, se verifica si las carreras del horario compartido están habilitadas en el dispositivo receptor. Si no lo están, se habilitan y sincronizan de forma automática.
  \item Detección de Duplicados: Se identifica si las materias ya están inscritas o aprobadas (SubjectStatus.APPROVED). Las materias aprobadas se omiten para evitar inconsistencias.
  \item Fusión Inteligente:
  \begin{itemize}
    \item Si la materia ya está inscrita en el mismo grupo, se actualiza la información pero se mantiene el estado.
    \item Si la materia está inscrita en un grupo diferente, se actualiza la inscripción al nuevo grupo.
    \item Si la materia no está inscrita, se crea una nueva entrada en SelectedSubjectRepository y se guardan los horarios en GroupScheduleRepository.
  \end{itemize}
\end{itemize}

El resultado de la importación puede indicar éxito total, éxito con duplicados (materias ya aprobadas o existentes) o fallo, permitiendo a la interfaz de usuario mostrar retroalimentación adecuada al estudiante.

\subsection{Resultados y verificación}
La interoperabilidad se valida mediante el intercambio exitoso de horarios entre dispositivos con diferentes configuraciones de carrera. Se confirma que el contrato JSON es robusto ante cambios menores de versión y que el proceso de importación maneja correctamente la fusión de datos sin generar duplicados, sugiriendo la sincronización de carrera cuando es necesario.
