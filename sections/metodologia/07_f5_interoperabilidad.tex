\section{F5: Interoperabilidad (JSON + WhatsApp)}

Esta fase se centra en habilitar un mecanismo robusto y estructurado para el intercambio de información académica entre estudiantes. Se implementa un contrato de datos basado en JSON que encapsula la información del horario, permitiendo su portabilidad y validación. Además, se integran flujos de exportación e importación que aprovechan las capacidades de las plataformas de mensajería instantánea modernas, facilitando la difusión de horarios sin depender de una infraestructura de servidor centralizada.

\subsection{Objetivo}
El objetivo principal es permitir que los estudiantes compartan e importen sus horarios de manera interoperable, segura y eficiente. Esto implica eliminar la necesidad de transcripción manual, reducir errores en la comunicación de grupos y horarios, y garantizar que la información compartida sea compatible entre diferentes versiones de la aplicación, preservando la integridad de los datos académicos del usuario receptor.

\subsection{Implementación de la interoperabilidad}
La implementación técnica abarca la creación de múltiples formatos de exportación, incluyendo representaciones visuales (PNG, PDF) y estructuradas (Excel, JSON). El núcleo de la interoperabilidad reside en un contrato JSON auto-contenido, generado y validado por componentes específicos de la capa de dominio. Se establecieron flujos de envío y recepción que utilizan los proveedores de contenido del sistema Android para interactuar con aplicaciones externas, incorporando validaciones estrictas de esquema y una lógica de importación idempotente que previene la duplicación de datos.

\subsection{Exportar}
La exportación es orquestada por el SettingsSendScheduleViewModel, que gestiona los estados de la interfaz y delega la generación de archivos a casos de uso específicos. Las opciones disponibles incluyen:
\begin{itemize}
  \item Imagen (PNG): Generada por GenerateWeeklyScheduleImageUseCase.
  \item PDF: Generado por GenerateWeeklySchedulePdfUseCase.
  \item Excel: Generado por GenerateScheduleExcelUseCase.
  \item Copia JSON: Generada por GenerateShareableScheduleJsonUseCase.
\end{itemize}

El proceso de exportación JSON permite una selección parcial de materias. El GenerateShareableScheduleJsonUseCase recopila la información académica (carreras, materias, grupos, docentes, aulas) y utiliza el ShareableScheduleJsonGenerator para construir el archivo final. La compartición se realiza mediante un Intent.ACTION\_SEND con un FileProvider, asegurando la compatibilidad con aplicaciones de mensajería como WhatsApp.

\subsection{Enviar copia (JSON)}
El archivo JSON generado sigue un contrato estricto definido en ShareableScheduleJsonGenerator. Este archivo es auto-contenido, lo que significa que incluye todos los catálogos necesarios para reconstruir el horario sin depender de una conexión a internet inmediata. La estructura del JSON incluye:

\begin{itemize}
  \item meta: Contiene la versión del contrato (version) y la versión mínima soportada (min\_supported) para garantizar la compatibilidad semántica entre diferentes versiones de la aplicación.
  \item careers: Lista de carreras implicadas (código y nombre) para permitir la sincronización automática si el receptor no tiene la carrera habilitada.
  \item subjects: Catálogo de materias para referencia.
  \item groups: Información de los grupos asociados.
  \item teachers: Datos de los docentes para enriquecer la visualización.
  \item classrooms: Información de las aulas.
  \item entries: Lista de las inscripciones (EnrolledSchedulePreview), que vinculan una materia y un grupo con un horario específico.
\end{itemize}

\subsection{Importar (desde WhatsApp)}
Al recibir un archivo JSON, la aplicación utiliza el LoadShareableScheduleUseCase para validar la integridad de la estructura y asegurar el cumplimiento del contrato de versión definido en los metadatos. Posteriormente, el ImportSharedScheduleUseCase orquesta la lógica de importación, la cual comienza verificando y sincronizando automáticamente las carreras faltantes si es necesario.

A continuación, cruza los datos entrantes con el repositorio local (SelectedSubjectRepository) para identificar materias ya aprobadas o inscritas, aplicando una estrategia de fusión inteligente que actualiza los grupos y horarios sin duplicar registros existentes, garantizando así la consistencia de la base de datos académica del usuario. Finalmente, el caso de uso retorna un resultado detallado (ImportResult) que informa a la interfaz sobre el éxito de la operación o la presencia de duplicados omitidos.

\begin{itemize}
  \item Sincronización de Carreras: Si el parámetro autoSyncCareers está activo, se verifica si las carreras del horario compartido están habilitadas en el dispositivo receptor. Si no lo están, se habilitan y sincronizan automáticamente.
  \item Detección de Duplicados: Se identifica si las materias ya están inscritas o aprobadas (SubjectStatus.APPROVED). Las materias aprobadas se omiten para evitar inconsistencias.
  \item Fusión Inteligente:
  \begin{itemize}
    \item Si la materia ya está inscrita en el mismo grupo, se actualiza la información pero se mantiene el estado.
    \item Si la materia está inscrita en un grupo diferente, se actualiza la inscripción al nuevo grupo.
    \item Si la materia no está inscrita, se crea una nueva entrada en SelectedSubjectRepository y se guardan los horarios en GroupScheduleRepository.
  \end{itemize}
\end{itemize}

El resultado de la importación puede indicar éxito total, éxito con duplicados (materias ya aprobadas o existentes) o fallo, permitiendo a la interfaz de usuario mostrar retroalimentación adecuada al estudiante.

\subsection{Resultados y verificación}
La interoperabilidad se validó mediante el intercambio exitoso de horarios entre dispositivos con diferentes configuraciones de carrera. Se confirmó que el contrato JSON es robusto ante cambios menores de versión y que el proceso de importación maneja correctamente la fusión de datos sin generar duplicados, sugiriendo la sincronización de carrera cuando es necesario.
