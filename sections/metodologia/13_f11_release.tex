\section{Fase 11: Release (parámetros y tamaños)}

Esta fase final del ciclo de desarrollo se orienta a la preparación exhaustiva del artefacto de software para su distribución y despliegue en entornos productivos. El proceso contempla la configuración optimizada del entorno de compilación mediante Gradle, asegurando que cada componente del sistema esté debidamente verificado antes de la generación del paquete final para el usuario.

Se aplican técnicas avanzadas de reducción de tamaño a través de herramientas como R8 y ProGuard, lo cual minimiza el peso del archivo binario y proporciona una capa de ofuscación de código esencial para la seguridad del software. Asimismo, se define una estrategia de entrega continua que garantiza la integridad del sistema y un rendimiento óptimo en la amplia variedad de dispositivos móviles de los estudiantes.

\subsection{Objetivo}
El objetivo principal es generar un paquete de instalación (APK) optimizado, seguro y eficiente, minimizando su huella de almacenamiento sin comprometer la funcionalidad. Se busca establecer un flujo de lanzamiento reproducible que asegure la compatibilidad con una amplia gama de dispositivos (API 24+) y gestione adecuadamente los recursos pesados, como los modelos de inteligencia artificial, fuera del paquete principal.

\subsection{Preparación del lanzamiento y métricas}
La preparación técnica para el lanzamiento se fundamenta en la optimización de los scripts de construcción desarrollados en Gradle. Este proceso asegura una gestión eficiente de los recursos y establece un entorno de compilación reproducible, garantizando que el artefacto final cumpla con los estándares de calidad exigidos para un entorno productivo real.

Se definen parámetros de compilación específicos, estableciendo un minSdk=24 para maximizar la compatibilidad con un amplio espectro de dispositivos modernos utilizados por los estudiantes. Asimismo, se utiliza un targetSdk=35 para aprovechar las últimas optimizaciones de seguridad, privacidad y rendimiento proporcionadas por las versiones más recientes del sistema operativo Android.

Para la versión de producción, se activa el motor R8 con las directivas minifyEnabled y shrinkResources. Estas herramientas eliminan automáticamente el código no utilizado y los recursos redundantes del binario final, aplicando una capa de ofuscación de código propietaria que protege la integridad y la propiedad intelectual del software desarrollado.

El entregable adopta una estrategia de descarga dinámica para el componente de inteligencia artificial, manteniendo el APK base bajo los 30\,MB al excluir el modelo LFM2.5-350M. Este modelo de 229\,MB se gestiona mediante el ModelInitializationService, asegurando una distribución ligera que optimiza el consumo de datos y almacenamiento en los terminales de los usuarios.

Este formato permite que la tienda genere y firme automáticamente los binarios específicos para cada configuración de dispositivo, reduciendo el consumo de datos durante la descarga inicial por parte de los estudiantes.

La evidencia recopilada confirma que la versión 1.0.9 (código de versión 10) se encuentra en estado plenamente activo y disponible para su descarga oficial en Google Play Store. Esta disponibilidad abarca una amplia gama de factores de forma, garantizando un funcionamiento fluido no solo en teléfonos móviles, sino también en tabletas y dispositivos con Chrome OS, lo cual amplía significativamente las posibilidades de acceso para el estudiante universitario.

Con un registro inicial de 27 instalaciones y la validación técnica de 18,599 modelos de dispositivos compatibles, el sistema demuestra una capacidad de distribución masiva y estable. Estos indicadores cuantitativos respaldan la robustez de la arquitectura implementada y aseguran que la herramienta pueda escalar de forma previsible y sin degradación del rendimiento ante un incremento constante en la base de usuarios activos.

Este hito de publicación definitiva garantiza que el artefacto de software ha alcanzado el nivel de madurez técnica necesario para su despliegue en el entorno productivo real. De este modo, se asegura un uso efectivo y autónomo del sistema dentro del ecosistema universitario boliviano, cumpliendo satisfactoriamente con los requisitos de fiabilidad, seguridad y disponibilidad planteados desde el inicio del proyecto.
